DNS 走向：客户端 → dnsmasq :53 → AdGuard Home :530，广告域名回 `0.0.0.0` → OpenClash :7874，境外域名回 `198.18.x.x` 的 fake-ip。AdGuard Home 停掉时，dnsmasq 改走 7874，上网不断。实测切换后的第一次查询要等约 3 秒，但能返回结果，不会失败。OpenClash 的 REJECT 规则在连接阶段再拦一次。

## 与 0.242 的差异

下面这些改动是为了适配树莓派的硬件，不要照搬回 R3 Mini：

- 单网口，没有 WAN 区。防火墙 lan 区开了 `masq=1`、`mtu_fix=1`。
- 风扇用的是 `scripts/rpi5-sidegw/fan/` 生成的树莓派版。R3 Mini 是反相 PWM：255 停、1 满速、0 禁写。树莓派是正相：0 停，75、150、255 分别是低、中、满速。两边不能互换。
- 不装 `r3mini-hotspot` 和 `r3mini-usb-web`，它们是 R3 Mini 硬件专用的。
- `r3mini_traffic.main.data_dir` 是 `/opt/r3mini-traffic`。`.242` 上是 `/mnt/mmcblk0p6/...`。
- `adspower-ph` 的 `listen` 必须是本机当前的具体 IPv4，`build_profile.rb` 不接受 `0.0.0.0`。地址变了要跟着改，见“换地方”。

另有一处软件设置和 `.242` 不同：树莓派的 AdGuard Home 设了 bootstrap 与 fallback `223.5.5.5`、`119.29.29.29`；`.242` 的 `fallback_dns` 是空的，因为它的基线要求本机不混入外部 DNS。所以 OpenClash 停掉时，树莓派的 AdGuard Home 会改用这两个公共 DNS，`.242` 不会。

| 改 IP 后 ttyd 还绑在旧地址上，新地址打不开终端。在 LuCI 里把 lan 改成 DHCP 也一样 | 执行 `/etc/init.d/ttyd restart`。没有终端时，在 LuCI「系统 → 启动项」里点 ttyd 的「重启」 |

| OpenClash 刚重启完，马上在树莓派本机访问 Google 失败，mihomo 日志里没有这条连接 | 刚启动的头几秒会出现。过几秒重试就返回 204。`lan_dhcp_fix.sh` 的这一项最多试 3 次，每次间隔 3 秒 |
| 按关键词 `password`、「密码」过滤 OpenClash 日志，代理账号那一行还在 | 那一行原文是 `...authentication of SOCKS5/HTTP(S) proxy with【user:pass】`，`user:pass` 处是实际的账号和密码，整行既没有 `password` 也没有「密码」（`/usr/share/openclash/yml_change.sh` 第 86 行）。过滤要带上 `authentication` 和「【」。`lan_dhcp_fix.sh` 按 `authentication\|password\|密码\|【` 去掉整行 |
| 从 PowerShell 5.1 调 ssh.exe 传含引号的远程命令，报 `ash: syntax error: unexpected "("` | 改用 Git Bash 调 ssh.exe，并设 `MSYS_NO_PATHCONV=1`。`scripts/rpi5-sidegw/pi.sh` 已经封装好 |
| OpenClash 日志 `[Warning] Can't Settting Only Intranet Allowed Function, Get IPv4 WAN Interfaces error` | 没有 WAN 区引起的，旁路由下可以忽略 |

## 换地方（搬到别的网络）

2026-11-10 起 lan 走 DHCP，OpenClash 改从 br-lan 读 LAN IP：`openclash.config.lan_interface_name=br-lan`，在 LuCI 里是「OpenClash → 插件设置 → 流量控制 → LAN 接口名称」。这样放到哪个网络都能拿到当地的地址和网关，OpenClash 不再依赖静态地址。2026-11-10 在办公室实测：OpenClash 启动成功；Google 解析成 fake-ip，百度能正常解析；SOCKS5 verify 返回 204；AdsPower 在 `192.168.1.245:10810` 上监听。树莓派本机用 curl 访问 Google 时，OpenClash 刚启动后的头几秒失败过一次。过一会儿重试返回 204，同时 nft 链 `inet fw4 openclash_output` 里 fake-ip 重定向规则的计数增加了（用 `nft list chain inet fw4 openclash_output` 查看），说明本机流量进了 OpenClash。

AdsPower-PH 例外：`build_profile.rb` 只接受具体的 IPv4，写 `0.0.0.0` 会报 `LISTEN_ADDRESS_MUST_BE_SPECIFIC_IPV4`。所以 `/etc/adspower-ph/settings.yaml` 里的 `listen` 要跟着当前地址改。

| 地点 | 地址 | 网关 | 依据 |
|---|---|---|---|
| 家 | `192.168.0.245`，静态 | `192.168.0.254` | 手动设置。家里的 DHCP 由 `.254` 发 |
| 办公室 | `192.168.1.245`，DHCP | `192.168.1.1` | 2026-11-10 在树莓派上读到 |

到了新地方、地址变了以后：

1. 查当前地址：在当地路由器后台的 DHCP 客户端列表里，找主机名 `immortalwrt-rpi5` 或 MAC `88:a2:9e:83:80:9c`。列表里找不到，多半是 lan 还是静态 `.245`（跑过 `adopt_local_gateway.sh`），这时按本节末尾的网线直连做法进去，先把 lan 改成 DHCP。
2. 打开 `http://<当前地址>`，确认 LuCI「网络 → 接口 → lan」的协议是「DHCP 客户端」。
3. 在 LuCI「系统 → 启动项」里重启 ttyd，再打开 `http://<当前地址>:7681`。ttyd 只绑在启动时的地址上。
4. 在 ttyd 里写入并运行脚本：先输入 `cat > /tmp/fix.sh <<'EOF'` 回车，粘贴 `scripts/rpi5-sidegw/lan_dhcp_fix.sh` 的全文，再单独输入一行 `EOF`，然后执行 `sh /tmp/fix.sh`。`'EOF'` 的单引号不能省，否则粘贴时 `$IP`、`$(...)` 会被提前展开。脚本做这些事：
   - 没拿到地址或网关时，什么都不改，打印提示后退出。
   - 把 OpenClash 和 AdsPower 的设置备份到 `/root/`。
   - 设 `lan_interface_name=br-lan`、`enable=1`，把 AdsPower 的 `listen` 改成当前地址。
   - 重启 OpenClash、AdsPower、sysntpd。
   - 逐项打印「好」或「坏」：OpenClash 进程、Google 解析成 fake-ip、百度解析、Google 访问返回 204（最多试 3 次）、SOCKS5 verify 返回 204、AdsPower 监听。
   - 有坏项时，打印 `/tmp/openclash.log` 的最后 15 行；含 `authentication`、`password`、「密码」或「【」的整行都会去掉。
5. 在当地路由器里给 MAC `88:a2:9e:83:80:9c` 做 DHCP 地址保留，以后地址就不会变。
6. 客户端上手动填的网关、DNS、SOCKS5（`:7896`）、AdsPower（`:10810`）都换成新地址。

搬回家后想用回 `.245`（家里的设备都按 `.245` 设置），有两种做法：

- 在家里主路由 `.254` 上给 MAC `88:a2:9e:83:80:9c` 保留 `192.168.0.245`，lan 继续走 DHCP，再跑一次 `lan_dhcp_fix.sh`。这样再搬走时什么都不用改。这种做法还没在 `.254` 上试过。
- 不方便在 `.254` 上做保留时，在 lan 走 DHCP 的状态下执行 `scripts/rpi5-sidegw/adopt_local_gateway.sh`：
  - 它先检查：当前地址在 `192.168.0.x/24` 里；默认网关存在且在 `192.168.0.x`；网关能通；`.245` 没被别的设备占用（当前地址已经是 `.245` 时跳过这一项）。有一项不满足就什么都不改，打印当前设置后退出。
  - 都满足时：备份 `/etc/config/network` 和 AdsPower 设置；lan 改成静态 `.245`，掩码 `255.255.255.0`，网关和 DNS 都用 DHCP 给的网关；OpenClash 的 `enable` 置 1；AdsPower 的 `listen` 改回 `.245`。然后在后台依次 reload 网络，重启 sysntpd、OpenClash、AdsPower、ttyd。
  - 改完后网关不通，就恢复 network 和 AdsPower 的备份，reload 网络，等 10 秒再重启 AdsPower；OpenClash 保持启用。后台日志在 `/tmp/office-fix.log`。回滚后 AdsPower 的 `listen` 是改之前的值，可能还是别处的地址，要再跑一次 `lan_dhcp_fix.sh`。
  - 从家里电脑执行：先在主路由的 DHCP 客户端列表里查到树莓派当前地址；也可以在 PowerShell 里用 `Get-NetNeighbor -LinkLayerAddress 88-A2-9E-83-80-9C` 查，但只有最近通信过的地址才有记录。把 `pi.sh` 里的地址临时改成它；在 `docs/私密/rpi5-sidegw/known_hosts` 里把 `192.168.0.245` 那一行复制一份，IP 换成当前地址（主机密钥不变）。然后在 Git Bash 里、仓库根目录下执行 `bash scripts/rpi5-sidegw/pi.sh -s < scripts/rpi5-sidegw/adopt_local_gateway.sh`（PowerShell 不支持 `<`）。地址回到 `.245` 后，把 `pi.sh` 改回来。

再搬走之前，如果 lan 是静态 `.245`，要先改回 DHCP，否则到了别的网段就连不上它。可以在 LuCI「网络 → 接口 → lan」把协议改成「DHCP 客户端」，保存并应用；也可以在树莓派上执行：

```sh
uci set network.lan.proto=dhcp
uci -q delete network.lan.ipaddr; uci -q delete network.lan.netmask; uci -q delete network.lan.gateway; uci -q delete network.lan.dns
uci commit network
( sleep 2; /etc/init.d/network reload ) >/dev/null 2>&1 </dev/null &
```

忘了改就搬走了，可以用网线把电脑直接接到树莓派，电脑设成 `192.168.0.100/24`，打开 `http://192.168.0.245` 再改。这一步还没实测过。

## 改 IP

本节只适用于 lan 是静态地址、并且在家里的 `192.168.0.0/24` 里换地址的情况，例如跑过 `adopt_local_gateway.sh` 之后。lan 走 DHCP 时，地址由路由器分配，要固定地址就在路由器上做 DHCP 保留。

2026-11-09 实测从 `.247` 改到 `.245`，下面以改成 `192.168.0.X`（同一网段）为例。

0. 先在电脑上确认新地址没人用：在 PowerShell 里，`Test-Connection 192.168.0.X -Count 2 -Quiet` 应为 `False`，`Get-NetNeighbor -IPAddress 192.168.0.X` 应没有有效的 MAC。新地址还要避开 `.242`、`.246`、`.254`。
1. 用旧地址的 SSH 会话执行：
   ```sh
   cp -a /etc/config/network /etc/config/network.bak-$(date +%Y%m%d-%H%M%S)
   uci set network.lan.ipaddr=192.168.0.X
   uci commit network
   ( sleep 2; /etc/init.d/network reload ) >/dev/null 2>&1 </dev/null &
   ```
   旧会话随后会断开。
2. 本地同步两处地址：`docs/私密/rpi5-sidegw/known_hosts` 里的 IP，以及 `scripts/rpi5-sidegw/pi.sh` 里的地址。
3. 用新地址登录，执行：
   ```sh
   /etc/init.d/ttyd restart
   /etc/init.d/openclash restart
   sed -i 's/^listen: .*/listen: 192.168.0.X/' /etc/adspower-ph/settings.yaml
   /etc/init.d/r3mini-adspower-ph restart
   ```
4. 网关 `192.168.0.254` 不变，不用改。
5. 通知使用者：把设备上手动填的网关和 DNS、SOCKS5 地址（`:7896`）、AdsPower 代理地址（`:10810`）都换成新 IP。
6. 更新本文和 `docs/必读/当前设备运行基线.md` 里写的地址。
