# 联网与浏览器

## 可以用谷歌浏览器

用户 2026-11-08 授权，并要求写进必读：可以用谷歌浏览器（Chrome）打开网页、读资料、下载资料。这条只放开 Chrome 这个工具。下载哪些文件、存到哪里、要不要先问用户，仍按当前任务的要求；任务没说清，就先问用户，并说明文件名、来源和大小。

什么时候换 Chrome：

1. 先用 searxng 或脚本取。
2. 被网站拦下就换 Chrome。被拦的表现：HTTP 403、拿到 “Just a moment...” 验证页、脚本拿到的正文是空的但浏览器里能看到。不要靠换 User-Agent 或反复重试去绕。

在 Chrome 里怎么做：

- Claude 用 Claude in Chrome 扩展，工具名是 `mcp__claude-in-chrome__*`；不要用内置浏览器面板的 `mcp__Claude_Browser__*`。Codex 用它自己的 Chrome 扩展。没有 Chrome 扩展的 agent 被拦时，告诉用户。
- 只在自己的标签组里新开标签页操作，用完关掉；不碰用户原来开着的标签页。Claude 先调 `mcp__claude-in-chrome__tabs_context_mcp`，没有标签组时带 `createIfEmpty: true` 建一个。用户把 Claude in Chrome 标签组列为不抢前台的方式。
- 全程后台：不把 Chrome 切到前台，不移动鼠标，不模拟全局键盘输入。
- 不改 Chrome 的设置，自动翻译也不改。
- 用户已登录的账号只为当前任务使用：不登出，不改账号设置，不替用户输入密码。
- 碰到验证码或人机验证就停下：告诉用户网址，标签页留着，等用户处理或决定。不替用户点，也不把浏览器的 cookie 交给脚本去绕开验证。

## 失败时

| 情况 | 处理 |
|---|---|
| Chrome 没开，或扩展报告未连接、没有响应 | 告诉用户，等用户打开 Chrome 或连上扩展；不改用会抢前台的办法 |
| 在 Chrome 里打开也是 403、验证页或空白页 | 停下，把网址和看到的页面告诉用户，由用户决定 |
| 下载后在下载目录里找不到文件 | 用 `(New-Object -ComObject Shell.Application).NameSpace('shell:Downloads').Self.Path` 查下载目录，按文件名找；还找不到就告诉用户 |

## 实测过的坑

2026-11-08 在 `https://www.raspberrypi.com/documentation/computers/raspberry-pi.html` 上实测：

| 现象 | 处理 |
|---|---|
| searxng 读网页报 403；PowerShell `Invoke-WebRequest` 报 `远程服务器返回错误: (403) 已禁止。` | 在 Chrome 标签页里正常打开这个网址，页面能加载 |
| 在已加载的页面里用 JS `fetch` 同一网址，拿到的仍是 403 的 “Just a moment...” 验证页 | 不用 `fetch` 取页面，直接用标签页里已经渲染好的页面 |
| 打开几秒后，Chrome 自动把英文翻译成中文，标题和正文都变了 | 要存英文原文：用 `mcp__claude-in-chrome__browser_batch` 把 `navigate` 和 `javascript_tool` 放进同一批，打开后马上用 `cloneNode(true)` 复制正文节点（这个网站的正文节点是 `#content`）。再用 `/[\u4e00-\u9fff]/g` 数副本里的中文字符，必须是 0；不是 0 就重新打开页面再复制 |
| 要把页面内容存成文件 | 在页面里用 Blob 加 `<a download>` 触发下载。`.md` 文件不弹任何窗口，直接存进 Chrome 下载目录，再移到任务指定的目录。下载目录以 `shell:Downloads` 查到的为准，本机是 `G:\Downloads` |

只实测过把页面正文存成 `.md`；在 Chrome 里直接下载 PDF 等文件还没实测过。
